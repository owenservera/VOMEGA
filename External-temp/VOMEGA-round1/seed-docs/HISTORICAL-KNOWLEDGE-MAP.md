# Historical Knowledge Map — How to Mine BCP-dev
VOMEGA starts clean, not amnesiac. Historical BCP-dev contains product thinking, implementation evidence, archaeology, experiments, migration work, and agent-system experience. Use it as a mine; do not recreate its structure.

Source: https://github.com/owenservera/BCP-dev/tree/main/docs

**docs/destination/** — richest destination corpus: North Star, principles, conceptual/human experience, provider/account/routing, data/memory/context, Work/agency/attention, Forge/evolution, world/workspace/canvas, maturity/gaps, system-intelligence, core/plugin, agentic-core, world-object/surface, plugin ecosystem, product-instance and self-knowledge studies. Mine durable concepts, contradictions, falsifiers, research questions, evidence, alternatives.

**docs/migration/** — forensic legacy→Ω work: browser/provider contracts, data models, mappings, risks, vertical slices, proof discipline. Mine behavior and failure lessons; migration architecture is not destination law.

**docs/agent-system/** — autonomous-development experiments: teams, communication, delegation, governance, workspaces, context, testing, reconciliation. Mine lessons; do not copy organization wholesale.

**docs/Reality-engine/** — prior work on trustworthy mutable machine/repository reality and Windows hazards. Mine failure lessons; revalidate prescriptions.

**docs/research/** — focused external/tool research including ZCode. Treat time-sensitive facts as historical snapshots.

**docs/archive/** — archaeology for lineage or lost behavior.

Historical docs mix observations, benchmarks, proposals, decisions-at-the-time, implementation detail, plans, speculation, and superseded conclusions. When mining: identify source/date; classify claim; check current reality; extract underlying problem/evidence; preserve contradictions; refresh time-sensitive facts; promote only after current evidence or explicit decision.

Do not import old decision IDs, workstream order, maturity numbers, agent rosters, branch conventions, or PM machinery merely to resemble BCP-dev. Preserve knowledge, not accidental structure.
