# Proof and Maturity — Honest Claims
VIVIM must distinguish “exists” from “works,” and fixture success from real product behavior.

A useful evidence ladder:
**Idea/Characterized → Mechanized → Verified → Live → Integrated → Productized → Sovereign/Evolvable.**
Refine labels if useful; preserve the distinctions.

## Proof rules
Fixture proof ≠ live proof. Loaded plugin ≠ verified realization. Login ≠ correct account binding. Process exit ≠ Work completion. Green unit tests ≠ integrated product behavior. Model confidence ≠ proof. Repeated historical claim ≠ current evidence. Successful external action ≠ correct authority/routing/account/outcome. Generated code ≠ admitted trusted capability. Old benchmark ≠ current performance.

When a claim crosses external reality, observe the intended substrate. For browser-mediated behavior, useful proof may need to establish selected account/session, outgoing payload, actual external result/effect, returned content/receipt, interpretation, persisted evidence, and cleanup. Exact mechanism is discoverable.

For important claims be able to trace:
**desired outcome → dependencies → implementation → evidence → current maturity → next falsifier/gate**.

## MVP discipline
A Minimum Viable Product is the smallest product slice that is genuinely useful and truthfully works for a real user. Minimum reduces surface; it does not lower the evidence standard. If one live seam blocks a promising MVP, the correct next product work may be the smallest unblocker experiment rather than a larger simulated product.

**Promotion is proof, not confidence.**
