# Workstream Landscape — Expected Problem Domains
These are coverage areas, not a mandated organization chart. Decide whether each deserves a department, temporary group, owner, workflow, or no special structure.

- **Product / MVP / Human Experience:** product slices, onboarding, first minute, mental model, universal prompt, configuration, installability, release fitness.
- **World / Data / Memory / Context:** identity, records, relationships, provenance, lifecycle, memory semantics, context, retrieval, freshness, projections, import/export/reconstruction, self-knowledge.
- **Semantic Interaction:** addressing, intent, capability resolution, ambiguity, deterministic semantics, natural-language control, explainability, probabilistic interpretation versus governed execution.
- **Authority / Governance / Trust:** consent, scope, delegation, refusal, policy, external mutation, provenance, admission/promotion, constitutional change, user control.
- **Work / Agency / Attention:** durable Work, agents, background execution, standing intent, scheduling, checkpoints, recovery, cancellation, idempotency, attention and continuity.
- **Provider / Account / Browser / Routing:** provider knowledge, account identity, sessions/profiles/resources, discovery, browser realization, protocol drift, routing, health, concurrency, healing, live proof.
- **Plugins / Composition / Forge / Evolution:** contribution boundaries, composition, capability gaps, authoring, generated artifacts, admission, compatibility, impact, migration, rollback, repair, self-extension.
- **Surfaces / Spatial Environment:** World projections, spaces/workspaces, visual paradigms, provider surfaces, direct manipulation, accessibility, representation boundaries.
- **Runtime / Constitution / Reliability:** trusted substrate, resources, persistence, evidence, failure/refusal, restart/recovery, performance, security, replacement.
- **Verification / Reality / Research:** independent truth-seeking, runtime observation, live-vs-fixture classification, falsifiers, benchmarks, contradictions, research, traceability.
- **Development-system effectiveness:** ZCode, parallelism, context, Git/worktrees, automation, test throughput, observability, collaboration, bottlenecks, validated throughput.

Split, merge, rename, or discard workstreams when evidence supports it. Coverage does not grant authority.

## Provider Lab coverage

The Provider / Account / Browser / Routing workstream should treat live human interaction evidence as a first-class research input alongside automated tests.

A persistent Provider Lab function may cover provider archaeology, capability mapping, Shadow observation, conformance, drift, recovery/healing, usage-weighted coverage, and promotion of proven provider knowledge into Ω.

This does not require a permanent department or a permanent extension architecture.

## Harvest responsibility

Every persistent problem domain should treat ecosystem archaeology and prior-art harvesting as part of engineering, not as an isolated research department's job.

R&D may coordinate difficult searches, but the workstream responsible for a mechanism remains responsible for understanding the strongest existing solutions before expensive reinvention.

Where repeated harvest work becomes high-value, create a temporary or persistent Harvest Bench rather than repeatedly starting from zero.
