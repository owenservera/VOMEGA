# Conceptual Model — Seed Vocabulary, Not Schema
This preserves a vocabulary for reasoning about VIVIM. It is not a database schema, class hierarchy, implementation mandate, or frozen ontology. Refine or reject concepts when evidence warrants it.

## Candidate concepts
**World** — persistent environment representing the person's digital reality and relevant context.
**Thing** — meaningful addressable entity.
**Relationship** — meaningful connection between things, with identity/provenance where needed.
**Space** — semantic/spatial context for organizing and experiencing things.
**Surface** — representation or interaction form; one thing may have many.
**Context** — task-scoped evidence-backed assembly of what is relevant now; not memory or authority.
**Attention** — what the person asks the environment to care about or what current state makes salient.
**Address** — who/what an interaction targets.
**Intent** — what the person means to accomplish.
**Capability** — semantic power available to the environment.
**Provider** — external system/service.
**Account** — person's authenticated relationship with a provider.
**Realization** — concrete implementation of a capability.
**Session** — concrete active execution relationship/resource.
**Routing** — policy for choosing among valid candidate realizations.
**Authority** — what may happen, for whom, under what scope/approval.
**Work** — durable outcome entrusted to the environment; workers are replaceable.
**Agent** — governed actor performing delegated Work.
**Evidence** — support for what was observed, produced, inferred, attempted, or claimed.
**Memory** — durable retained knowledge/state with semantics and lineage.
**Time** — history and continuity.
**Configuration** — user-owned choices about behavior, presentation, routing, attention, retention, automation, or policy.
**Composition** — combining capabilities, things, surfaces, triggers, data, and policy.
**Plugin** — explicit replaceable contribution boundary.
**Forge** — ability to create, modify, compose, repair, replace, and evolve governed capabilities/surfaces.

A useful reasoning chain is:
**World → Context → Focus/Address → Intent → Capability → Choice → Authority → Work → Evidence → Memory → evolved World**

This is not an implementation pipeline.

Protect useful distinctions: reality ≠ representation; evidence ≠ authority; intent ≠ execution; capability ≠ realization; provider ≠ account; account ≠ session; discovery ≠ routing; routing ≠ authority; memory ≠ context; Work ≠ worker; World ≠ surface; Space ≠ World; confidence ≠ proof.

Candidate human verbs: See · navigate · focus · inspect · address · ask · create · connect · configure · run · delegate · approve · refuse · verify · remember · replay · recover · share · export · forge.
