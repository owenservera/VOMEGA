2. Read `PROJECT_START_HERE.md`, the neutral 00/01 contracts, owner v0.5 doc, then initial audit. Inventory the rest through paths/hash/semantic lookup first; do not load 391 files into a context blindly.
3. Run AUDIT-R0 and AUDIT-R1 as read-only passes. For each documented conflict provide verbatim short quote, paths and current SHA. Inspect actual consumers before proposing to move anything.
4. Parallelize genuinely separable reviewer questions across product, architecture, executable evidence and adversarial navigation. Prove worker independence if claimed. Have a separate verifier reconcile findings.
5. At each bounded round, write a source-pinned findings report, decision delta and explicit PASS/FAIL/NOT_RUN gate. Do not pretend the audit is an Elephant development turn; active development teams still obey the existing every-turn full portfolio contract.
6. Continue through R2–R8 only while the next experiment could change a concrete decision. Enforce the complete gate/disposition rules in REVIEW_SEQUENCE.md.
