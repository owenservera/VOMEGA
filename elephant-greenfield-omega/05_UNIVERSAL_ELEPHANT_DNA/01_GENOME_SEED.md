# 01 — Universal Elephant DNA: Candidate Genome v0.1

## Definition and distinction

An **Elephant** is a durable, bounded cognitive *role* whose knowledge basis, operating self-model, competencies and communications can be inspected and reconstructed independently of any single model conversation. It has no inherent code-writing, account-spending or governance authority. A user-visible personality, enormous context window or persistent chat handle alone does not establish Elephant identity.

A **gene** is an observable competency obligation. It is *not* a process, model instinct, source code file, microservice, prompt, storage table or mandatory technology choice. A gene qualifies as universally inherited only if it remains necessary across distinct use cases and can be falsified separately from one specific implementation. All twenty are **candidate**, pending external comparison.

## Three unifying ideas to test

**Cognitive metabolism:** information ingress, transformation, allocation, retrieval and egress consume time/tokens/storage and can be compared for **validated utility per full lifecycle cost**. Compression without fidelity is loss, not optimization.

**Cognitive topology:** an Elephant reports where its knowledge overlaps with peers and can *propose* splitting, sharing, merging or moving boundaries. Topology changes require orchestration permissions and proof, not unilateral mutation of another Elephant.

**Cognitive continuity:** cognitive identity means restored, source-grounded competencies—not reattaching to the same conversation or dumping a transcript. Rebuild, reload and live persistence are competing realizations.

## Minimal genotype versus candidate full genome

Begin fitness research with six cross-cutting phenotype tests, not implementation of twenty subsystems:

1. **Inventory:** honestly state known/read/not-read domains, omissions and source epochs.
2. **Resources:** report measured/estimated/unknown tokens, capacity, cost and latency.
3. **Exchange:** communicate a source-bounded answer to another Elephant with integrity and trace.
4. **Invalidate:** detect changed support and refuse stale certainty.
5. **Reconstruct:** rebuild independently and pass matched competence probes.
6. **Improve:** identify a real friction signal and compare one candidate remedy to a baseline.

The six tests **sample** several genes; they do not prove the remaining genes by association. A minimum viable genotype is an experimental shortlist, not a permanent exemption from later obligations.

## Intrinsic capability vs environmental mechanism

Every proposed gene must identify: what the Elephant can know or decide; which external measurement/safety capability is needed; what observable evidence separates real behavior from confident self-description; and what failure it must communicate. Example: a model may request token accounting but cannot inspect hidden inference state unless the host exposes it. A source index may confirm which bytes were supplied but not prove the model understood them. A bus adapter may transport messages but does not by itself make peers mutually knowledgeable.

## Universalization test

Before accepting a gene as core, run it against at least three distinct domains with a controlled no-Elephant baseline. Try to falsify universal necessity: could the role achieve the same independently verified competency with a small wrapper or generic tool alone? If yes, keep the **observable competency** but do not mandate internalizing that tool. If the competency is genuinely specialized, move it to a role-specific phenotype profile.

Owner decisions, E0 controls and existing product proof gates take precedence over aesthetic elegance or a fixed number of genes.
