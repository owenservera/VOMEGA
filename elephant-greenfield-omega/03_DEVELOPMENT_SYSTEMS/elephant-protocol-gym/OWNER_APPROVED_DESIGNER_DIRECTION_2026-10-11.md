# Owner-Approved Designer Direction — Elephant Gym Archaeology, Self-Hosting, and Experimental Priority

**Decision status:** OWNER APPROVED, 2026-10-11, following review of [Legacy Semantic Archaeology and Reuse](PROPOSAL_LEGACY_SEMANTIC_ARCHAEOLOGY_AND_REUSE_2026-10-11.md). **Scope:** Gym designer research direction, scope and evaluation priority. **Not:** approval to merge legacy implementations, ratify a particular software architecture, self-authorize effects, start external agent sessions, or claim any Gym capability has passed tests.

## Approved disposition

**Retain the archaeology proposal as a historically grounded, useful intelligence pack. Do not treat it as the master Gym architecture or execution/launch protocol.** Its proposed MP-21, NLCL and Phase 0 comparison experiments remain available. New discoveries and superior alternatives are welcome; implementation requires independent evidence and reviewed promotion.

**Primary thesis to challenge experimentally:** The Semantic SDK becomes the common, source-grounded command/meaning/Wiki/visual interface through which both human users and Elephants eventually **inspect, understand, govern, develop, test and improve everything that is code or controls code in VOMEGA — including the SDK, all developer tools and Elephant operating protocols themselves**.

This is a *target and testable research claim*, not current implementation truth. Every stream should try to falsify it, expose its limits and compare to simpler controls.

## Five approved designer corrections

1. **Broaden intelligence recovery:** MP-21/NLCL/semantic-mutation archaeology is one portion of a larger body of prior Elephant intelligence. Include ECP (O1 and independent Claude alternatives), general Z.ai A/B/C fan-out, Claude v0.2 round executor/evaluator, Universal Elephant DNA and its ablations, context/flush/rotation/recovery, handoffs, source custody, publications, failed experiments and incomplete candidate packs. Preserve provenance, original counterarguments and current status; private/inaccessible code is marked unavailable. Use [preservation index](ELEPHANT_INTELLIGENCE_PRESERVATION.md) and [existing feeder](FEEDER_REUSE.md); **do not create a new harvesting platform by default**.
2. **Self-governance is the primary SDK acceptance target:** Source-linked Command → canonical machine meaning → Human/Wiki explanation → machine-readable visual/spatial representation → explicit authorization → actual test/tool witness → discrepancy → tested revision. The staged [U0–U5 universal code/tool interface requirement](UNIVERSAL_SEMANTIC_GOVERNANCE.md) applies across SDK, tools, runtime, agent context, Elephant configuration, protocols, coordination, fan-out and evaluator systems. After verified U4 enrollment, normal supported changes to that domain must use the command interface; until then bounded bootstrap and authorized recovery are explicit.
3. **Visual intelligence is foundational, not deferred polish:** High-density human/spatial representation and **machine-readable visual assertions** must reflect the same source/command/effect/evidence state, with independently testable actual rendering and comprehension. Cosmetic icon/theme/layout/3D customization must not mutate machine command chains or hide material consequences. Semantic edits via visual interactions produce a new validated command revision. Use [core visual language](CORE_VISUAL_LANGUAGE.md).
4. **Adaptive experiments rather than a predetermined integration plan:** Maintain blind-discovery vs seeded-reuse controls and genuinely independent fan-out, isolation, pre-registered cases, held-out tests, independent evaluation, recoverable ledgers and every-turn all-maturity pack publication where the execution environment supports them. Elephants may propose KEEP/SPLIT/MERGE/REASSIGN/RETIRE/ADD/REPLACE of their own organization, but claims require actual trials; host budget/authority and owner canon decisions stay external. Use [adaptive swarm](ADAPTIVE_SWARM.md), [existing experiment practices](../SHARED_EVIDENCE_PRACTICES_FROM_CLAUDE.md), and the actual earlier [Claude v0.2 round tools](../proposal-specific/claude-zai/runtime/pack/team/README.md) as *candidate reusable experimental machinery*, not mandatory implementation.
5. **Require one independently reconstructable end-to-end learning witness before scaling complexity:** Work on real pinned SDK/Elephant source, explain a real implementation or operating behavior through the shared Command/Wiki/visual meaning system, execute an authorized harmless local test, capture raw witnessed outcome, expose a deliberate discrepancy, propose an isolated improvement, replay baseline/negative probes, and give the evidence to a fresh independent Elephant for reconstruction. If any portion is only design/simulation/not run, say so explicitly. The initial witness can be headless for semantic truth, with truthful staged spatial parity verification; do not claim full 3D UI acceptance from a headless projection.

## Evidence-priority sequence (not a waterfall)

- **P1: Reality-based self-explanation.** One Elephant explains and tests its actual SDK/tool/protocol behavior, with exact source and evidence.
- **P2: Safe self-adjustment.** A real Elephant operating setting, context policy or handoff mechanism can be proposed, changed under permission, replayed and reverted through shared semantics.
- **P3: Verified visual/machine parity.** High-density human visual meaning, machine-readable visual contract, revision handling and reprogrammable themes/interactions preserve semantic command chains and visible safety.
- **P4: Experimentally justified parallel self-organization.** Compare E0, E1, E2 and adaptive multi-stream configurations against simpler controls, including communication, context and total integration costs.

Archaeology, preservation, compiler experiments and alternative designs may proceed in parallel. **Priority does not mean blocking independent exploratory research.** Scaling organizational complexity *as a success claim* depends on evidenced learning, not number of sessions.

## Approved change boundaries

- **Original archaeology proposal stays unchanged:** it remains a source-inspected, not-independently-rerun research reference with proposed experiments, not an approved migration plan.
- **No imposed final schema/architecture:** pure TypeScript NLCL, Reflection graph, Python Phase 0 runner, Node/Claude executor, browser, Wasm, 3D renderer and ECP candidates must be compared, not silently required as universal internals.
- **No new authority:** user approval here is for research direction and priorities, **not** a grant of unrestricted external actions, credential use, automatic recursive spawning, unilateral product-goal rewrite or automatic main-branch integration by agents.
- **Keep original benchmark vs evolving destination separate:** the frozen Greenfield Ω simulated seed remains intact; authoritative MVP v0.5 is [mvp/NORTH-STAR.md](../../../mvp/NORTH-STAR.md), with owner-approved Gym overlays and explicitly versioned requirement epochs.
- **All historic Elephant intelligence must remain discoverable and falsifiable:** retain accepted and failed pack lineages, disagreements and source availability; no undocumented replacement of the earlier general A/B/C system by Claude's two-track system.
- **No self-certification:** source assertions, model explanations, Wiki renderings, agent-reported success and beautiful dashboards do not substitute for independent process/test/user evidence.

## Designer handoff and review obligations

At the next Gym design pass, the designer must (a) acknowledge these five corrections, (b) publish a **source-linked recovery/coverage matrix** of significant earlier Elephant assets and missing artifacts, (c) propose the **smallest actual self-hosting experiment** with baseline, independent falsifier and command↔wiki↔visual receipt, (d) identify reusable parts of earlier fan-out/isolation/evaluation/assimilation protocol rather than redeveloping it, (e) map encountered code/tool/protocol areas to U0–U5 honestly, and (f) identify one reversible organizational change that may be tested after initial evidence.

**Success criterion:** a fresh independent researcher can understand what prior Elephant research concluded *and what failed*, use existing runnable instruments where proven, and reproduce a real SDK/Elephant self-learning result without privileged hidden chat context.

**Current state:** direction approved, experiment NOT_RUN, no new Elephant sessions launched, no archaeology code merged or promoted solely by this decision.
