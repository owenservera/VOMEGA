## The owner directive

**The Semantic SDK must fully embed the *capabilities and semantic discoverability* of the development tooling needed to build, inspect, test, experiment with and improve itself.** The SDK and Elephant operating system of protocols are the first substantial **self-hosting test corpus**. Before expanding the product, prove that the Elephant can learn **how its own system actually works** through the shared **Command → Meaning → Source-grounded Wiki → Bounded Test/Execution → Witness/Evidence → Revision** circuit.

“Fully embed” here describes an *integrated, complete user/agent capability surface*, **not** an order to make every compiler, code indexer, test process, and harness one inseparable browser/Wasm bundle. A small typed SDK and its adapters can expose and describe independently replaceable tools. Real tools can be invoked in controlled development environments; a single-file HTML shell may be a portable *view*, and a headless lab can consume the same meaning/protocol. Experiments may challenge that modular split, but not source/evidence or effect boundaries.

## What an Elephant must be able to ask and verify about itself

At minimum, it should be able to investigate:

- **Identity and architecture:** What code, commit, plugin, capability, semantic rule, session context, agent protocol and tool are actually loaded? Which are merely documented or proposed?
- **Self-knowledge:** Which function/source declaration implements an action? Which wiki facts, tests, dependencies and prior observations support its explanation? What remains unobserved?
- **Interpretation:** What command did a human or Elephant mean, what alternative readings exist, what symbols or spatial gestures map to it, and what is incomplete?
- **Its own developmental actions:** What happens when I run a baseline, inspect a TypeScript file, compare two interpretations, compile a small change, mutate a fixture, inspect dependency impact, or publish a capability pack?
- **Context and coordination:** What files/context was this Elephant given? What did it select or omit? What changed when it handed off to another Elephant? Which requests were sent/received, and were they grounded?
- **Failure and correction:** Which protocol step caused a mismatch, where can a human see it, what test would falsify the suspected cause, and did the fix improve the measured run without erasing old evidence?
- **Authority:** What is readable, runnable as a harmless local test, or requires explicit approval? What source/World/runtime state was actually present?

A Wiki claim about a protocol is **not** evidence the protocol executed; a planned worker is not a live worker; an invented test trace is not a witness.

## The first dogfood execution circuit

```text
Human text / Elephant command / canvas semantic action
                     ↓
           SDK semantic interpretation
     typed candidates • gaps • source and context epoch
                     ↓
   ONE REVISION-BOUND SEMANTIC PUBLICATION
     ├─ Machine / agent / symbolic projection
     ├─ Human-readable Plain Reading + contextual Wiki
     └─ Shared 3D canvas representation and status
                     ↓
      Explicitly gated local development tool
     source inspect • graph query • test • replay
     compare • mutation • Wiki refresh • pack export
                     ↓
      ACTUAL output, traces, errors, hashes, receipts
                     ↓
         Human ↔ Machine ↔ source comparison
                     ↓
  Independent check → proposed source/protocol change
       → isolated test → accepted/rejected finding
                     ↓
   SDK and Elephant operating knowledge updated
         through the EXISTING feeder/review rules
```

The engine's *self-description, human explanation and external test witness* must be distinguishable. Enter-to-publish freezes semantic meaning; it does not automatically grant permission to execute untrusted generated code or reach external systems. Only a bounded, authorized tool action executes in the test environment.

## Tooling as a self-describing SDK surface

The SDK's design target includes **all of the following discoverable and invocable capability groups**, as replaceable adapters with typed inputs, effects, preconditions, outputs, evidence and test hooks. This is a **capability inventory, not a ratified API list**:

1. **Source feeder and custody:** list sources; find and pin files, blobs, declarations and imports; check source hash/freshness; recognize missing private inputs. Reuse [FEEDER_REUSE.md](FEEDER_REUSE.md).
2. **Semantic compiler/interpretation:** lex and parse ordinary TypeScript and human/symbolic intent; ground candidates; expose semantic identity, alternatives and contradictions; compare projections. Reuse [NLCL/symbol intake](SYMBOLIC_LANGUAGE_INTAKE.md) as an evaluated control.
3. **Source-native Wiki / Reflection:** extract structurally justified facts; resolve symbols, dependencies, impact and affected tests; show what the SDK and Elephant can *actually* do. Compare [MP-21 Reflection Migrator](../../../../omega-baseline/experimental/reflection-migrator/README.md) against alternatives; source-Git-commit-only scans must not pretend to see uncommitted changes.
4. **Build and test:** discover available tool versions and run only allowed compile/typecheck/unit/property/golden/negative probes in an isolated workspace; capture exact command, exit status, stdout/stderr, environment and source revision.
5. **Experiment runner:** freeze baseline/holdout; generate/accept mutations and alternative interpretations; compare implementations, protocol formats and corrections with a separately held oracle; track runtime/effort and fidelity. Reuse [Phase 0 existing developer tools](AUTOMATION_REUSE.md) and [automated semantic experiment design](LEGACY_ALIGNMENT_MAP.md), rather than creating another harness by default.
6. **Context/protocol observability:** discover session capability declarations, source/context allocation, received context, compression losses, missing references, handoff receipts, communication state, epoch/authorization boundaries, stale requests and protocol changes. Use the Elephant's *actual* witnessed sessions/packets where available; otherwise label simulation.
7. **Self-improvement and change analysis:** state a falsifiable design hypothesis, propose a small SDK/tool/Elephant-protocol change, preview affected facts/tests, replay baseline, compare, rollback or request owner review. Do not allow an agent to certify itself.
8. **Release and reuse:** emit complete capability packs of every maturity/failure state under the [existing all-turn publication contract](../../01_EXPECTED_OUTPUTS/02_EVERY_TURN_PUBLICATION_CONTRACT.md); expose findable source/evidence references to future Elephants. No second release ledger.

**No mandatory consolidated software kernel yet.** The first implementation can call existing tools and project their source-grounded meaning through one SDK semantic interface. Embedded *capability completeness and introspectability* comes before physical binary unification. The SDK should eventually describe its own adapters and protocol operations using the same source/evidence standard applied to user capabilities.

## A corpus Elephants can actually test on themselves

The first corpus is not only natural-language commands or toy arithmetic. It is **the SDK/Gym's own source and operating behavior**:
- Pin the [Gym seed, launch rules and current review contract](README.md), a small TypeScript fixture, and a selected real source/control from [existing feeder](FEEDER_REUSE.md).
- Inspect real **NLCL `symbols.ts`, `lexer.ts`, `interpret.ts`**; compare historical symbol claims with code and identify a witnessed ambiguity or code-claim gap.
- Inspect **MP-21 Reflection Migrator** source, its reported local tests and its Git-revision limitation; experiment with truthful source-linked Wiki answers.
- Inspect **Phase 0 Live/Experiment/Change** implementations; contrast correction proposals against independently adjudicated regression evidence.
- Inspect **D1 virtual World/safety gates** and **Elephant dogfood/ECP/DNA source/packs** with correct MOCK/PARTIAL/NOT_RUN labels.
- Treat an Elephant's own generated run note, context selection and handoff as source data for subsequent tests; ask a fresh Elephant to reconstruct the same supported behavior from the published artifacts.
- Retain adversarial questions and deliberately wrong statements as negative controls. Preserve discoveries that refute the expected design.

See the small [starter dogfood corpus](corpus/self-hosting-cases.json). These are **proposed named test cases**, not an automated executable suite or independent pass claims. Each one identifies an observation and its falsifier; agents may derive more tests but cannot silently rewrite referee holdouts.

## The primary Phase 0 benchmark: Can the Elephant explain and improve its own protocol?

A first genuinely useful vertical slice lets an Elephant use a **command to ask why a particular SDK/Elephant behavior happened**, receive a source-grounded Wiki answer with version and unknowns, execute one authorized local probe, see the **actual** result, expose any Machine/Human/spatial discrepancy, suggest a bounded change and publish enough evidence that another independent Elephant can reproduce or falsify the claim.

The minimum independently testable acceptance path is:
1. **Real self-knowledge:** name one real SDK/tool/protocol source declaration and its pinned revision; answer a relevant command through the Wiki and clearly distinguish CODE_DERIVED / DECLARED / OBSERVED / UNKNOWN.
2. **Tool discovery:** query which real local build/test/protocol tools exist, their requirements and allowed actions; no hallucinated available executors.
3. **One executed harmless local test:** save its command, input, environment, exit status and witness. If the harness cannot run, declare NOT_RUN and fail the execution acceptance condition.
4. **One deliberate mistake:** inject a false wiki statement, stale source fact, wrong symbol meaning or mismatched Elephant handoff; reveal the discrepancy and produce a minimal repro and correction proposal.
5. **One measured iteration:** make a small isolated change to the semantic SDK *or* Elephant operating protocol, rerun matching baseline and negative probes, describe differences and preserve rollback.
6. **Independent reconstruction:** a fresh session can inspect the source and all-state capability pack and arrive at the same **supported** conclusion without depending on unrecorded chat memory.
7. **Spatial parity:** the first interactive canvas instrument shows the same publication identity, source epoch, effect/authority distinction and observed status as machine and human Wiki outputs. Headless SDK tests can validate the same semantics before the 3D implementation is complete.

No pass can be claimed merely by a generated proposal, a model's self-rating, a synthetic reply mistaken for a real tool output, or an external provider UI simulated in mock mode.

## Research freedoms, staging and scope

**Phase 0-A — Observability before redesign:** minimal source → command → Wiki → tool result → evidence path, using existing components where possible. Start by making one Elephant operating protocol visible and testable. **Phase 0-B — Self-modification under observation:** compare competing semantic/compiler/wiki/context/protocol changes with independent checks and deliberate failure injection. **Phase 0-C — Operating-system cognition:** multiple Elephants inspect, communicate, repair/replay and improve the same SDK and their own handoff/coordination rules. These are candidate experimental milestones, not a waterfall or forced teams; representation and feedback occur in all slices.

Success is **measurable learning about how the Elephant system functions**, not breadth of product features, lines of code, number of concurrent agents, sophistication of the 3D renderer or apparently complete wiki pages.

Preserve [legacy capability alignment](LEGACY_ALIGNMENT_MAP.md) as a **post-run completeness check**, not ten mandatory modules; keep [WebAssembly](WASM_BOOSTER.md) optional; keep [full 3D canvas and shared Machine–Human manifold](INITIAL_STATE.md) in view throughout. Other independent architectures, runtimes, transports and artifact packaging remain experimentally open.

## What is still a hypothesis

That one general semantic compiler can faithfully represent arbitrary self-operating protocols; how code/agent-context/evidence identity should be encoded; which tools can run inside a browser; which should remain isolated outside; what human-comprehensible protocol introspection should look like; how self-modification affects test trust; which SDK functions are necessary; which tool adapters are worth retaining. **Do not answer these by assuming a comprehensive all-in-one SDK already works.** Design a specific small witness, then learn.
