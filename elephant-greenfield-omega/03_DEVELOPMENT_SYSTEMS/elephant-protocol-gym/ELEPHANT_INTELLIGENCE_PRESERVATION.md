## One refeed workflow; no competing knowledge platform

1. **Discover:** use existing asset lookup/discovery indexes and source/tree inventory. Include historical proposals, raw failures, code, experiments and actual results. Enumerate missing input and stale snapshot identifiers.
2. **Custody:** pin exact repository/blob/commit, artifact checksum or publication ID, scope, rights/sensitivity and source epoch. Files described only by metadata are not executable source.
3. **Classify:** ORIGINAL_SOURCE / HISTORICAL_ASSERTION / DESIGN_CANDIDATE / IMPLEMENTED_CODE / AUTHOR_REPORTED_TEST / REPRODUCED_TEST / REJECTED / FAILED / UNAVAILABLE. Evidence class is not a single scalar confidence.
4. **Crosswalk:** map historical idea or tool to current SDK capability and updated owner requirement; preserve conflicting versions and alternatives. Do not overwrite the original architecture with one presumed universal gene.
5. **Challenge:** run a small pinned comparative experiment and negative probe against a fresh competitor/independent oracle. Separate blind discovery from legacy-seeded reuse.
6. **Project:** expose discoverable semantic source facts, Human/Wiki explanations and machine-readable visual assertions; no claims of currently running Elephant, host concurrency, or finished 3D renderer without actual witnesses.
7. **Refine:** promote only owner-reviewed shared canon changes; preserve the original rejected hypotheses/failing cases and new evidence in the existing every-turn capability publication system.
8. **Maintain coverage:** flag work not yet incorporated into the SDK at U0 indexed/knowledge stage, and specify its next falsifiable step toward U1–U5. Old intelligence is retained **even if not implemented**.

## Key non-loss invariants

- Never replace prior Z.ai A/B/C experimental independence with Claude's A/B-only implementation silently.
- Never conflate model sessions, agents, experiment arms, Elephant cognitive nodes, tracks or worktrees.
- Never make a proposed simulator or scripted consult into a LIVE independent cognition claim.
- Never overwrite the sealed experiment basis, accepted test or owner requirement with later conclusions.
- Never force a fixed architecture or inherited set of 20 Elephant DNA traits merely because a prior document listed them.
- Never lose failed, incomplete, retired or unchanged capability packs during reorganization.
- Never assume a human-visible graphic proves the semantic state, or a machine representation that lacks visible safety information offers true human parity.
- Never allow direct config/code/tool execution to silently bypass the shared command interface after that domain has passed its applicable U4 progression gate.

**Evaluation question:** When a fresh Elephant asks “what have previous Elephants learned about this source/protocol/tool, including what failed?”, can the SDK return the dated, source-grounded, dissent-preserving evidence and an actionable test, without guessing about inaccessible artifacts?
