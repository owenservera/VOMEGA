# Shared Evidence Practices Learned from Claude v0.2 (Cross-Architecture)

These are **candidate lab-quality requirements**, not a new mandated universal runtime, chosen programming language, final Elephant subsystem list, or full imported Claude team process. They apply to the unrestricted general lab and future independently launched proposal-specific Z.ai development systems when feasible, without retroactively modifying active Round 1.

## Incorporate as minimum evidence obligations

1. A durable, append-verified event history with reproducible integrity checks, explicit run/turn/arm identities, recoverable pending requests and privacy rules. Claude supplies a hash-chain JSONL implementation for local mechanical study, not a requirement to copy it or claim tamper-proof storage.
2. Frozen experiment claims: task cohort/hash, public acceptance criteria, evaluator holdouts, usage budget, selection rules and applicable source/model versions must be locked before candidate results can influence them. Changes create new cohort/version.
3. Derive labels from evidence: a failed or absent child-context/permission/parallelism probe is LIMITED/UNKNOWN, never PROVEN; a scripted assistant or simulated control is not a real isolated subagent. Capture observed nonce separation and actual runtime overlap.
4. Use independent evaluator staging and reproducible deterministic checks. Anonymous/staged contestant output and withheld tests help mitigate contamination, but need actual independent evaluator contexts and permissions. For hosted Z.ai, prove this rather than assuming anonymity.
5. Test operational failures intentionally: tampered event history, unexpected file writes, leaked canary, lost session, missing artifact, duplicate request, changed contract, stale citation, absent token report, failed restart and incomplete hidden oracles.
6. Separate candidate self-reports from objective tests. For scoring, freeze primary quality criteria and compute objectively reproducible fields; expose original metrics and sensitivity rather than letting a model tune post-hoc weights.
7. Equip any dashboard with independent data-verification checks, rather than accepting agent-produced charts or screenshots. A reloaded application should produce the same ledger status, lineage and accepted result.
8. Preserve unpromoted learnings with context, evidence, scope and revisit condition. Two masters independently assimilate *locked* results; cross-track import is versioned and separately tested.
9. Publish complete capability portfolios **after every bounded top-level development turn**—including pre-evaluation Turn A, blocked/no-work turns, all maturity states and unchanged packs—with durable immutable refs and source/evidence content. A publication is not an independent quality endorsement.
10. Independently judge E0/E1/E2 and architecture scopes using real accepted software outcomes, total wall time, model tokens/cached categories or UNKNOWN, implementation/build overhead, recovery cost, and demonstrated source trust.

## Not incorporated globally

Do not require: exactly two turns and a manual oracle key; fixed C1–C8 final system parts; Node/Next.js/Prisma/SQLite; identical Claude team-specific commands; a two-track-only system that displaces the current general A/B/C; source-quote-only ECP as the sole permitted architecture; all code in a permanent Track A/Track B main; or any hidden-oracle score when key custody/independence is not proven.
