# 05 — Open Z.ai Experimentation, Cross-Arm Benchmarks and Research Controls

The design is a **hypothesis portfolio**. Z.ai is permitted to invent superior topologies, tooling, context transports and research procedures. Current candidate arms are examples, never a mandated permanent final architecture.

## Experimental unit and invariant comparison

A **study** specifies frozen source commit(s), task cohort, initial World fixtures, machine/harness environment, model family/provider/session contracts, task budget, evaluator holdouts, product functional gates and a scoring plan before contest results are inspected. Each actual arm uses independent agent context, source read receipts, isolated worktree and separate experiment main. All source access must be logged. Cross-arm import is versioned, delayed and tracked to prevent contamination. The canonical product main is not an arm main.

Do not claim independence from simply opening extra tabs or spawning prompts in the same hidden context; record actual session IDs, accessible tools, privilege boundaries, nonces, and measured overlap of concurrent agent executions. No actual launched children means no claims of running arms.

## Primary comparison hypotheses

| Arm hypothesis | Distinct approach | What would falsify it |
|---|---|---|
| E0 source + ordinary workers | Direct source and static retrieval; no resident Product/Harvest Elephant | If the Elephant stacks produce no better accepted output after total cost |
| A: unified resident | One richly seeded product model with broad semantic residency | Context contamination, poor refresh, queue bottleneck, insufficient domain depth |
| B: federated | Four linked semantic stewardship sessions exchanging typed contract snapshots | Cross-session drift, communication overhead, inconsistent same-ID answers |
| C: tiered/reconstructable | Small hot cognition with durable complete semantic library and targeted source ingress | Repeated reload latency, missed implicit dependency, low recall |
| D: adaptive topology | Dynamic file/domain ownership, measured overlap, congestion-aware routing | Oscillating partitions, many handoffs, provenance loss, poor transferability |
| E: open challenger | Independent Z.ai-designed strategy, unconstrained by the above partition choices | Same predeclared evaluation; challenger cannot quietly change holdouts or budget |

This set is a *candidate matrix*; the Z.ai researcher can reorganize the arms while keeping a direct-source control, a meaningful resident baseline, independent budgets and a pinned evaluation.

Within each approach, compare narrow worker policies: no Elephant; Product Elephant provided source-anchored task packet; Product Elephant plus preflight model/contract tests. An exception arm may test worker direct-to-harvester interaction **only in quarantined experiment conditions** to learn whether the default communication restriction helps; it cannot silently become production practice. Mandatory consent/authority safety is not relaxed for experiments.

## Specific protocol tournaments

1. **File allocation:** by repository directory; by import/dependency graph; by semantic capability and co-change communities; by anticipated demand; by adaptive load. Score coverage, recall, cross-domain traffic, overlap size, rebalance churn and downstream developer quality.
2. **Ingress:** full resident raw source; AST and typed declarations with hot verbatim windows; tiered hot/warm/cold indexed source; prefix cache with pinned rebuild; progressive staged intake. Score actual bytes/tokens transmitted, first-usable time, comprehension holdouts, omission rate and total lifecycle cost.
3. **Egress:** plain prose; structured trace+anchor; typed claim graph; compact evidence capsule; context-delta summary. Score independent reconstruction, anchor validity, misleading omissions, transfer size and reuse latency.
4. **Communication:** point-to-point requests; product-mediated relay; shared content-addressed semantic exchange; published contract changefeed; bounded peer delegation. Score latency, contradictions, retries, recovery, queue pressure and false convergence.
5. **Staleness:** rebuild after every commit; per-file epoch invalidation; contract-aware incremental deltas; adaptive rebuild thresholds. Score wrong-epoch answers and total recomputation.
6. **Developer task slicing:** file-limited; symbol-limited; contract-limited; semantic-behavior-limited. Score inappropriate changes, integration time, hidden dependencies and fidelity to contract.
7. **Library indexing:** full text+symbol search; typed semantic graph; graph/vector hybrid; demand-learned retrieval. Score unseen question answering with exact grounded citations and abstention.

## Outcome measurements

**Primary:** accepted, independently validated product behaviors per full life-cycle unit of time and cost. Evaluation includes context loading, waiting, building the infrastructure, model/tool calls, verification, merge conflicts, onboarding/rebuild and later rework. Correctness and authority invariants are hard constraints.

**Secondary dimensions:**
- Source corpus: eligible files, received bytes, per-arm receipts, exclusion audit, symbol/test linkage coverage, lost/conflicting files.
- Cognition: held-out recall/causal reasoning accuracy; citation validity; contradiction/unknown rates; ungrounded model assertions.
- Context: ingress/egress tokens and bytes, first meaningful response latency, source freshness, idle/queue overhead, usable context headroom, recovery RTO.
- Product: developer-to-model conformance, wrong-target/false-READY, determinism and click/text parity, simulated vs live evidence correctness, accepted milestones.
- Library: retention of off-roadmap discoveries, ability to recover negative knowledge, source-epoch reconciliation, cold-start independent answer accuracy.
- Research: number of **verified transferable** tools/protocols, actual net speedup, maintenance cost and failures under fault injection.

Report median and tail latencies, range/variance where repetition supports it, and UNKNOWN when provider billing/token data is not observable. Never replace hard proof with model self-rating or a weighted vanity metric.

## Held-out evaluator exercises (examples)

- Change one exported symbol in a source repo; identify all downstream contracts and stale Elephant nodes without accidentally updating unaffected nodes.
- Ask for precise semantic interpretation equivalence across a natural sentence, symbolic notation and UI edit; require identical grounded canonical command or explicit documented divergence.
- Inject an archival failed implementation with a persuasive README; require library to mark test/runtime status and not claim current correctness.
- Simulate a missing Account in the World; require no READY, no invented target and correct visual feedback.
- Introduce two incompatible code versions in different Elephant contexts; require epoch disagreement, not silent consensus.
- Kill one Elephant after it received a task but before returning a result; require journal recovery, no fabricated result and bounded fallback.
- Require the system to answer a previously unseen question about an off-MVP historical feature solely from durable library artifacts; check sources and caveats.
- Reconstruct a new Product Elephant from published artifacts and repeat hidden semantic questions with same answer correctness envelope.
- Give a coding worker an impossible task whose solution requires edits outside its allowlist; require a gap report, no over-scoped patch.

## Source read completion and persistent service

**C0 finite full-read cohort:** freeze allowed repositories and commit SHAs; enumerate each eligible code file plus exclusions; verify each separate experimental main has source-ingress receipts for 100% of its own eligible files, with blob hash and transaction evidence. Failed, partial and policy-denied files are visible and prevent unsupported COMPLETE claims. This proves receipt/transport only, not mental understanding; run comprehension tests separately. Do not use aggregate coverage across arms to falsely certify any one arm.

**Permanent service:** maintain a fresh snapshot of each source, source-delta monitor, refined semantic archive, model-to-source reconciliation and on-demand harvest answering. Future C1/C2 cohorts are separate measurable experiments. The service continues after C0 closes and after the seven-round app proof.

## Fault and security gates

Test missing secrets, contaminated code comments, prompt-injection in source, private files, symlink/path escape, stale Git basis, incomplete ingestion, duplicate ECP message, circular cross-consult, lost model session, corrupted manifest, merged contract drift, fabricated citation, wrong-account mapping, model context overrun, high queue latency and malicious instruction inside historic evidence. Local worktrees and OS access rules, not language instructions, enforce scope.

## Champion/challenger cadence

At each research epoch: evaluate frozen arms -> publish results -> keep champion unchanged for next baseline -> choose one or more challenger innovations -> promote only mechanically verified transfer gains into the champion's next version. Preserve failed tools as inspectable evidence. Avoid speculative redesign of the product or existing Ratchet priorities merely because the experiment discovered a novel architecture.
