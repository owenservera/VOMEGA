# 06 — Two-Track Seven-Round Roadmap: Working MVP + Usable Corpus Library

**Owner's product aspiration:** a floating Windows text box, natural-language Provider/Account setup, governed prompt submission to three AI webapps (ChatGPT, Claude, Gemini), adaptive contextual command-center UI, and a source-derived auto-Wiki. A full installation-to-live-send claim requires owner-approved provider automation and independently observed webapp outcomes; synthetic simulations are labelled SIMULATED and never counted as live success.

**Delivery form:** fixed externally useful behavior per round; tactics and precise subsystem implementation are open to Z.ai. Each round yields (a) app proof, (b) semantic-library proof, (c) a tested Elephant process/protocol improvement or a truthful record that no candidate paid off, (d) a complete per-turn/round portfolio publication.

## Definitions and honest partial proof

- A round passes only its actual implemented/observed gates; a documentation outline or mocked window screenshot is not a working app.
- R6 full ingestion means exact code-file transport/coverage plus structural extraction and held-out corpus utility. It **does not** claim every line was deeply understood or every possible relationship extracted. The separate C0 full-read finish certificate remains per independent main; delays are explicit and do not create fictitious successful rounds.
- If R5 live provider proof is blocked by policy, capability or consent, isolate genuine working local behavior and the blocker; R7 live claims remain blocked. Continue permitted simulated and non-live research rather than trying to evade the boundary.
- Initial product targets are not equivalent to implementing all historical capabilities. Off-MVP records remain in the queryable semantic library and may become future candidates without current execution rights.
- User-facing auto-Wiki is **derived** from installed source declarations/Reflection and runtime evidence; historical library may be an attributed research source but never a substitute for source-derived current behavior.
- Progressive UI means current capability and context drive disclosure; it is not a second UI action interpreter.

## Each round is decomposed into bounded work packets

Product Group owns a multi-round dependency map but only issues workers narrowly scoped current tasks. Each packet must enumerate approved file/symbol scope, behavior, non-goals, source/model epoch, test oracle and route for escalating uncovered dependencies. As source changes, the Product Group revises later-round plans. Workers cannot autonomously negotiate broader goals, read Harvester chats or bypass the Product gateway. Independent evaluator can still test directly against raw source and frozen acceptance cases.

## Roadmap scheduling principle

The roadmap is **outcome-based, not an imposed sequential architecture**. R1/R2 language + Reflection foundations and R4 library ingestion can advance in parallel where dependency/test isolation permits; cross-semantic contract changes require ordered integration. Z.ai may reorder internal work if it preserves the externally verified seven milestones and records why. No permanent separate product branches: short-lived task worktrees and experiment-specific temporary mains only. Product Ratchet and owner-selected PM scope remain existing execution truth.

## At R7, ask these independent questions

1. Can a new user perform the entire targeted journey without a developer editing config files?
2. Can the command system correctly explain why a wrong/unknown Account, missing consent or stale browser session prevents READY?
3. Does typing or clicking change the same canonical command state with deterministic replay?
4. Can the source-native Wiki explain a currently loaded command from current code and evidence, not merely historical notes?
5. Can a newly launched, context-empty agent query historical semantic concepts *not used in the MVP* and recover original source, evidence maturity, related concepts and contradictions?
6. Can the library index the entire eligible C0 cohort, detect a new commit, and refresh only affected claims without losing negative history?
7. Can a fresh Product Elephant be reconstructed from durable artifacts and pass independent conformance questions?
8. Were workflow tooling investments worth their true cost compared with direct-source and simpler alternatives?
