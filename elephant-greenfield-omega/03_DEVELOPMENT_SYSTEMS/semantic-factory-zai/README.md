# Ω Elephant Semantic Factory — Permanent Use Case v2.0

**Design proposal / portable Z.ai handoff. Not launched. No VOMEGA repo changes.**

This package extends the previously prepared v1 source harvest charter into a full **product-directed, self-improving Elephant engineering and semantic library program**. It carries two equal acceptance streams: an independently verified seven-round Windows natural-language command MVP; and an automated, source-bound semantic corpus library useful beyond the MVP.

**Key design choices:** unified Semantic Product Elephant Group (library + NL/symbolic compiler + visual language + Reflection/auto-Wiki), Harvest Elephants directed by the Product Group and by a systematic archival intake obligation, narrowly scoped coding workers receiving all AI task instructions through the Product Elephant gateway, independent evaluator and integrator, genuine competitive experiments, full per-turn pack release, and explicit freedom to invent/revise tools and protocols. Number/placement of Elephant sessions, topology, storage and tooling are experimental choices.

## Design/proof distinctions

- Current Ω Git source, owner decisions, authenticated runtime evidence and executable tests are authoritative. Product Elephant cognition is advisory/source-grounded; archived code is historical evidence.
- C0 frozen source **transport ingress** completion is a finite benchmark, and requires per-arm 100% eligible-file receipts. It does not prove understanding. The permanent service updates after C0.
- All source must be preserved/inventory indexed, but only tested current declarations are operational Ω semantics. Keep useful unconsumed corpus knowledge with source anchors and maturity labels.
- No direct Harvester-to-Worker channel. Worker can read allowed current source and run tests; its only AI product instructions come from its assigned Product Elephant gateway. OS/tool access enforces scope.
- The 17 symbolic families exist at lexical level. Do not claim complete semantics for every glyph. `!` never bypasses required consent.
- Auto-Wiki is a source/runtime Reflection projection, not a separately authored authority database.
- Z.ai may challenge the proposed internals and invent better methods in isolated experiment arms. Evaluation is outcome-driven; a new tool that reduces overall validated throughput is not a victory.
- Every top-level agent turn and research round publishes the **complete** content-addressed portfolio of proposed/partial/failed/verified/retired packs and comparisons, regardless of maturity.
- No provider/config/auth/model changes or consequential live webapp effects without owner/appropriate authority.
