# Acceptance Gates, Fault Injection and Safety Constraints

## Hard gates

G0 — source seed/import and permitted filesystem scope are proven. G1 — one real model/tool task executes with durable provenance. G2 — four separate subagent contexts, safe workspace isolation and verifiable concurrent overlap. G3 — independent evaluator replays tests. G4 — measured/unknown token accounting and parent-child aggregate reconciliation. G5 — deterministic epoch/staleness checks. G6 — context rotation/reconstitution without promotion of rejected draft content. G7 — E0 direct baseline measured and retained. G8 — E1 consult proves real model residency or labels stateless equivalent. G9 — E2 actually has two distinct live Elephant sessions and contradiction/freshness checks. G10 — two current master approaches and four new next-round experiments recorded.

Every gate has a state PROVEN / FAILED / LIMITED / UNKNOWN, evidence, verifier and timestamp. Blocked critical gates do not become automatically accepted via textual reassurance. A single agent narrative is not independent evidence.

## Round-specific exit criteria

Round 0: actual utilities implemented/tested, four isolated child attempts with proof, event ledger, minimum cockpit and model call. E0 rounds: no Elephant, no hidden consultation or global memory, reproducible benchmark. E1 rounds: one identified context node, valid request/response with source anchors, real refresh and fallback proof. E2 rounds: two concurrent nodes, domain split/overlap, genuine cross-node consultation, disagreement case and congestion measurement. A round cannot be marked COMPLETE without 4 qualifying arms; if conditions prevent it, mark BLOCKED/INCOMPLETE and preserve partial evidence.

## Failure injection suite

- One worker times out; another crashes mid-write; a third is cancelled; fourth completes. Verify logs, worktree isolation, replay and cleanup.
- Rate-limit or exhaust one provider; prove degrade to another allowed lane/E0 rather than conceal usage.
- Change a shared contract after Elephant snapshot; make sure stale flags are mechanically surfaced.
- Supply contradictory answers from two Elephants; record disagreement with a falsifier and don't silently pick a winner.
- Force duplicate request/retry; verify idempotency and lack of duplicate external side effects.
- Interrupt database/backend during event write; replay without losing or double-counting child events.
- Trigger context compaction/rotation; calibrate model answer quality and evidence references before and after.
- Inject a seeded bug that a large-context reviewer should catch; compare with fresh worker and deterministic checks.
- Leak attempt via sibling workspace canary; fail isolation gate if detected.
- Vary missing token usage, mismatched context limits, or corrupt data; make the cockpit flag unknown/invalid rather than calculate fake totals.

## Security and privacy boundaries

No provider credentials or account cookies in prompts, source snapshots, logs or exported archives. No untrusted seed commands executed before inspection. Use least privilege for every worker; Elephants read-only by default; proposed patches are quarantined and independently checked. No secret copying, arbitrary public deployment, production database modification or automatic external webapp actions. Minimize retained raw model conversations; logs must have retention and redaction policies. Read-only provider auth configuration is protected.

## Economic stop rules

Stop or downscope an experimental feature if quality degrades, bottlenecks move to synchronization, token/latency overhead exceeds avoided reconstruction, context staleness cannot be controlled, or the lab's infrastructure work begins materially delaying the real Ω seed product. Keep two master approaches as research variants, but don't retain expensive always-on models when no useful work justifies them. Any persistent context deployment must earn its refresh budget.

## Final proof standard

A credible milestone is a repository state plus reproducible task tests, runnable backend/UI, four independent captured child runs, measured ledger, evaluator report, context/epoch proof, and two separate master next versions. Merely generating documents, mock screenshots, sample JSON, or an attractive cockpit cannot satisfy the milestone.

## Additional acceptance and falsifiers for Track C (2026-10-11)

A full three-track round needs C1/C2 as two extra actual child/worktree executions, a runnable third C candidate, proof C-Design saw only locked prior A/B work, independent C-Benchmark operator identity, Truth reviewer signoff and matched task/source cohorts with feature-age bias declared. Reject invented agent sessions, self-grading, changed holdouts, hidden setup/operational costs, unverified framework installs and unknown token numbers labelled zero. A/B R1 completion and full A/B/C R1 completion are separate states. See 21_TRI_TRACK_BENCHMARK_AND_REPORTING.md.
