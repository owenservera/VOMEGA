# Concrete Round Ladder — Four Real Theories Per Round

These are starting candidates; the two masters must preregister, refine and replace the next four theories using evidence. No round is complete without four actual context-isolated executed arms and independently graded outcomes. Two arms belong to each master. A/b masters remain **two candidate architectures**, while E0/E1/E2 denote active Elephant counts and must not be conflated.

## Round 0 — Utilities (E0 execution substrate proving ground)

- A1: Child launcher/context and worktree isolation including adversarial cross-access.
- A2: Per-parent/child token, tool, quota and event accounting with provider-reported versus estimated proof.
- B1: Source-pack manifest, Git epoch, stale-consultation and flush/rebuild proof.
- B2: Real full-stack persisted cockpit/UI linked to actual backend and child event records.

Goal: prove the tools needed to run later rounds. Failure on core isolation/provenance means do not claim completed fan-out. Even during Round 0, masters separately assimilate all four lessons to retain two runnable strategy candidates.

## Round 1 — Establish E0 ground truth (zero Elephants)

- A1: Plain repository-first fresh worker implementing a core command/target registry slice, with exact time-to-first-verified-edit.
- A2: Fresh worker + deterministic task-focused context bundle on an equivalent hidden fixture; measure correctness and setup overhead.
- B1: Stateless brief + source dependency index on a variant of the fan-out engine; compare against direct repo exploration.
- B2: Minimal task guidance with precomputed fixture/test anchors; attack whether context building itself costs more than it saves.

Null: already well-instrumented fresh workers are enough. Output: E0 baseline distributions and a known cost/quality floor. This round may be repeated with more matched fixtures before E1 is justified.

## Round 2 — First genuine Elephant (E1)

- A1: Long-lived resident command-domain Elephant performs architectural consultation before a worker implements a shared command contract change.
- A2: Same resident Elephant reviews a worker-submitted full artifact/patch; compare missed-dependency recall and false positives.
- B1: Rebuildable stateless packed-prefix context serves consultation on comparable held-out changes; measure token/latency break-even against persistent session.
- B2: Hybrid selective source files + verified domain notes versus full-source residency; attack whether context size improves accuracy at acceptable cost.

Require a real contextualized model node with distinct session identity for the resident arms; B arms can deliberately be nonresident alternatives. Include E0 anchors on matched tasks, not a separate fabricated Elephant. Confirm no source writes by the Elephant and all generated patches staged for worker review.

## Round 3 — E1 durability and context lifecycle

- A1: Append-delta wave refresh with source changed after node load; measure stale detection, refresh latency and citation validity.
- A2: Fork/isolate each transaction where supported; otherwise compare bounded append-plus-rotation; inject discarded proposal and detect pollution.
- B1: Deterministic full rebuild on domain change; check calibrated questions, cost, restart portability and reproduction after failure.
- B2: Adaptive prefetch/selection of relevant exact files; compare correctness versus simplest task context bundle.

Hard acceptance: context claims must be reconstructable at a known Git epoch, and a hard flush/rebuild must pass an independent integrity test. A provider `/compact` button alone is not proof.

## Round 4 — Two simultaneous Elephants (E2)

- A1: Domain-first complementary resident nodes (e.g. Command and Provider) jointly review a contract seam and produce a disagreement record where appropriate.
- A2: One Elephant routes a cross-domain concern to the second through explicit controller mediation; benchmark latency, congestion and source-citation fidelity.
- B1: Two independently rebuilt stateless domain specialists provide separate answers; evaluator checks boundary blind spots and inconsistent epochs.
- B2: Single larger context versus two smaller contexts under matched budget and task; test whether second-node complexity pays for itself.

Require two actually live/independent concurrent Elephant contexts for the arms claiming E2; B2 is deliberately a negative challenger. Include E0/E1 benchmark anchors and full context-load, refresh and coordination costs.

## Round 5+ — Adaptive cognitive orchestration, only if earned

Candidates: dynamic domain split/merge based on query hit-rate and saturation; routing based on measured marginal utility rather than model prestige; failed-model fallback and congestion control; context pack generated by Elephant versus deterministic builder; code-writing Elephant patch suggestions versus advisory only; high-risk migration review; disagreement-to-falsifier compiler; multi-model diversity; inter-round learned test fixtures; cross-provider token and context economy.

## Research discipline

For every new arm ask: what concrete uncertainty will it resolve, what observation would falsify the favored theory, what is the simpler E0 alternative, how will the judge reproduce the result, and what will each of the two masters be allowed to learn after results lock? Avoid four variations that differ only in prompt adjectives, button color or agent names. Reuse the same task complexity, hidden fixtures and model budgets when comparing alternatives, and measure coordination overhead rather than amortizing it away.
