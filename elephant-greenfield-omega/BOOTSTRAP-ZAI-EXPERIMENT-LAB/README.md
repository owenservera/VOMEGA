# ELEPHANT LAB — Z.ai Full-Stack Bootstrap Pack

**Documentation-only / bootstrap edition / 2026-10-11.** This pack intentionally contains no implementation source code, executable scripts, API credentials, fabricated metrics, or pretend experimental output. Its purpose is to instruct a real coding environment to **build and operate** a living experimentation platform, starting from an arbitrary project seed.

## Start in 60 seconds

1. Give the chosen agent a dedicated, initially empty laboratory workspace. Do not give write access to the user's original project until it proves safe isolated execution.
2. Provide the seed project spec in `05_SEED_PROJECT_AND_FAIRNESS.md`. The suggested demonstration seed is the greenfield Ω Prompt Fanout Mini defined in `../02_GREENFIELD_OMEGA_PRODUCT.md`; a different project is permitted if its requirements and benchmark tasks are frozen.
3. Paste **all of `01_PRIMARY_BOOTSTRAP_PROMPT.md`** into Z.ai Full-Stack mode. Supply this pack as project/reference files if the interface supports it; otherwise paste `01_PRIMARY_BOOTSTRAP_PROMPT.md` followed by the seed brief. Start with the exact same task in other candidate harnesses only when comparing platforms.
4. Insist on a **Round 0 capability and utilities proof**: four separately executed, instrumented, isolated probes before any claims about full Elephants, speedup, or production readiness. See `06_ROUND_ZERO_UTILITY_PROVING_GROUND.md`.
5. If hosted Z.ai Full-Stack cannot prove independent agent contexts, isolated workspaces, and per-run evidence, keep it as a cockpit/frontend builder and use a verified external harness such as ZCode for the experiment execution. Do not quietly substitute a single chat with four labels.
6. At the end of *every* round, retain exactly two independently evolving master approaches, four or more completed/attempted actual execution arms, evidence-based intake/rejection decisions by both masters, and a next-round plan. A missing/blocked arm is reported as failed—not counted as a completed real experiment.

## Governing distinctions

- **Two master approaches ≠ two Elephants**. Master A and Master B are independent evolving implementations/strategies. E0, E1 and E2 are Elephant deployment levels under evaluation within those approaches.
- **Four experiments ≠ four headings**. Each must have a separate job ID, verifiable execution identity, isolated context and workspace, measurable input/output, timestamps, tests, and preserved evidence.
- **No code in this pack ≠ no code in the experiment**. The commissioned agent must write real code, build the full-stack cockpit, run tests, launch model calls and evolve working candidates.
- **New knowledge ≠ accepted truth**. Hypotheses and Elephant suggestions never outrank source, automated checks, or experimental evidence.
- **No permanent owned Git branches**. Long-lived approach state lives as reviewed artifacts/implementations on a single consolidated main. Short-lived worktrees are disposable execution isolation.
