# Track C — Lagged Ecosystem Integration Challenger
Amendment to Elephant Greenfield Ω, 2026-10-11. Design and operating instructions only; no live execution claimed.

## Mission
The laboratory now has **three independently runnable implementation strategies** but keeps the **original two primary competing masters**:
- **A:** persistent, resident-context-first Elephant cognition.
- **B:** deterministic/reconstructable, context-bundle-first Elephant cognition.
- **C:** ecosystem-first, maximizing use of proven protocols, reusable tooling and mature runtimes where evidence shows improvement.

C is NOT the third Elephant. E0/E1/E2 still mean zero/one/two concurrent Elephant cognitive sessions. Track C must implement those levels when eligible, not claim them through UI labels. C builds its own working candidate and additionally operates the reproducible A/B/C benchmarking and publication pipeline. **An independent Truth evaluator—not C—owns holdout tests and signs official results.**

## One-completed-round lag — hard information boundary
At research round n, **C-Design learns only from locked A/B round n-1, plus its own history**, never unpublished A/B round n material. Its ability to inspect live ongoing A/B workspaces must be prevented by separate permissions/worktrees and a scoped evidence release, not a verbal instruction.

| Active research round | A/B live activity | C development input | A/B may assimilate |
| --- | --- | --- | --- |
| R1 (now) | Original four R1 experiments, unchanged | Locked A/B R0 only | prior locked R0 |
| R2 | Original four R2 experiments | Locked A/B R1 only | Locked C R1 findings, independently |
| R3 | Original four R3 experiments | Locked A/B R2 only | Locked C R2 findings, independently |
| Rn | Original four Rn experiments | Locked A/B R(n-1) only | Locked C R(n-1), independently |

The **separate C benchmark operator** may evaluate current Rn submissions only AFTER A, B and C freeze their candidate/source snapshots. That evaluation access must not leak into C-Design. C's benchmark report is a proposed publication until the independent Truth judge verifies it.

If R0 lacks authentic closed evidence, say BLOCKED and reconstruct read-only records; do not invent the missing round. Do not restart or mutate the already-running Round 1.

## Six-arm round rule
Maintain A1, A2, B1, B2 as **four mandatory original experiment executions**, each its own context and workspace. Add C1 and C2 as **two additional real, independently context-isolated** experiments comparing different tooling theories. A completed three-track round therefore requires **six genuine experiment executions**, with IDs, session provenance, isolated workspace roots, code/tool output, test evidence, usage/missingness and failure records. Four original A/B arms alone can still complete under the original A/B contract; call the sidecar three-track result INCOMPLETE until C actually executes.

The top-level controller launches children. If the chosen agent runtime forbids subagents spawning their own subagents, let the controller spawn C1 and C2 directly. Roleplaying several experts in one model conversation does not count. Concurrency must be demonstrated by overlapping actual child runtimes before claimed.

## Distinct actor responsibilities
- **A and B masters:** two different frontier approaches, two theory tests apiece, independent evaluation of all locked results and individual adoption/rejection of improvements in their NEXT round.
- **C-Design master:** builds a third runnable candidate from only released n-1 A/B evidence and independently approved shared primitives; owns tooling hypothesis selection but does NOT own grading.
- **C-Researcher:** consults primary upstream standards/framework sources and records exact version, license, security boundary, relevance and adoption costs.
- **C1 and C2 workers:** separate live model sessions and worktrees; each tests tool-backed implementation vs smallest practical native alternative. Artifacts are runnable, not just a literature survey.
- **C-Benchmark operator:** executes pre-frozen evaluation on A/B/C after source submission lock; does not modify candidates, holdouts, rubric or clock/budget records.
- **Truth judge:** isolated from all three implementations; controls hidden tests, independently reproduces results and signs benchmark verdict.
- **Controller/keeper:** handles source epochs, identity, data permissions, event ledger, publication and safe short-lived worktree integration.

C's design context must not share a thread/model history with its benchmark operator or the Truth judge. If separation cannot be proven, downgrade benchmark to UNVERIFIED PROVISIONAL.

## C's own iterative loop
1. Read authenticated previous-round A/B evidence and C's own locked historical results.
2. Diagnose bottlenecks and map them to public tools/standards.
3. Preregister two distinct hypotheses with controls and rejection thresholds.
4. Launch isolated C1/C2; build actual components, exercise real tool/model calls, run negative and restart/cancellation tests and collect source hashes.
5. Compare tool-backed vs native integration across behavioral coverage, source truth, cost, isolation, latency, portability and maintenance burden.
6. Construct one separately runnable C-next candidate incorporating only independently verified gains.
7. Freeze C version alongside A/B when round closes and offer to operator; do not access current-round A/B private designs.
8. Publish candid accepted/rejected standards and precise evidence; feed validated result to A/B in following round.
9. In following round C gets newly locked A/B prior-round evidence and repeats the search, while A and B independently decide which C capabilities to reuse.

## Standard adoption gates
Each candidate must identify an observed bottleneck, exact upstream spec/version/license, minimal integration plan, permission/security review, native control, at least one real functionality and failure test, dependency/ops overhead, rollback path and independent measured gain. Preserve ECP-specific Git epoch validity, source anchors, read-only cognition, context flush/rebuild, distinct model session proof, transaction metadata and tool-token observability.

Do not install frameworks merely because they are popular; prefer **one standard boundary + a small ECP adapter** over building a heavyweight interoperation platform. Never change provider credentials or running worktrees to satisfy an experiment.

## Success and failure
The goal is best **accepted verified Ω capability per full lifecycle time/cost**, not minimum original code or number of installed tools. A productive C iteration may demonstrate that the native solution is superior and reject a framework with reproducible evidence. A and B must remain meaningfully distinct and may import individual tested C mechanisms without converging wholesale. Honest failed attempts, poor quality, missing token fields and one-round age disadvantage must remain visible.
