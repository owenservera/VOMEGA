# Sealed evaluator protocol — NOT_RUN

All inputs in this repository are public developer tests. None is advertised as secret, blind or uncontaminated. Private holdouts were not generated in this builder session.

Before the next competition, a separate evaluator must write new prompts without seeing the grammar or candidate outputs, obtain independently adjudicated intended commands, and freeze an ID, SHA manifest and scoring thresholds outside candidate workspaces. Do not publish plaintext holdouts in Git, candidate images, shared mounts or model context. A committed digest alone does not make a leaked set blind.

Use at least six strata: account/provider/model/session confusion; quoted target words as payload; alternative argument boundaries; Unicode/bidi/confusables; stale display/source/permission; expiry/replay/concurrent dispatch. Separate language fidelity from authorization attacks. Include valid controls and intended abstentions; a reject-everything candidate must fail utility thresholds. Human understanding requires actual participants, not a syllable score.

Run identical inputs across frozen candidates in isolated, disposable processes/containers/VMs with network denied, no host credentials, read-only inputs, bounded CPU/memory/output, and explicit timeouts. Installation is part of the untrusted workload. This lab has **not** implemented or certified that execution substrate; its intake only reads bounded response files.

The referee should preregister zero accepted unauthorized effects, zero unflagged false READY on the adjudicated safety subset, a separately reported coverage threshold, and matched-cost comparisons. Publish aggregate denominators and failure classes. Release minimal redacted witnesses only after a round; rotate disclosed cases into public regressions and create a new sealed cohort. Keep failed or blocked runs in the ledger.
