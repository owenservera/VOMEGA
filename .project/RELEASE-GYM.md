# First Product Release Gym cycle

2026-10-05. The seed referenced a canonical Gym in BUILD-FOCUS.md but did not
contain its mechanism. The added short loop derives from bootstrap, MVP and
proof guidance; it is an operational repair, not a prewritten roadmap.

| Candidate | Value / actual readiness | Main risk and smallest falsifier | Disposition |
| --- | --- | --- | --- |
| Selected-vault local continuity | J2/J8 foundation; existing real host/law/storage; install/default path broken | fresh process recovers A, B misses A; external copy refuses without consent | **Selected first unblocker and implementation slice** |
| Live provider observation → local receipt | closest to J1/J5/provider anchor; only fixture adapters exist | establish reachable transport and Account evidence; disconnected browser cannot claim live receipt | **Next experiment**, read-only before any provider submission |
| Owner export → persistent conversation | useful J2/J8 alternative; pure parsers/chat store present | missing writer; repeated imports preserve source identity/time/provenance | alternative if browser seam unavailable |
| Local console orient/interpret/refuse | backend and semantic operations present | no UI, fictional providers, exposed root service; cannot call it provider beta | defer UI until an actual bottleneck |
| Data export/reconstruction | strong existing CAS/changelog roundtrip | verified data copy is not full Product Instance restore | secondary recovery slice |
| Delegated background Work | high future value, transient pools present | no durable Work; kill mid-action and distinguish interruption/uncertain effect | defer broad engine, retain crash falsifier |
| Floating control center / full Lab mirror | visible but speculative benefit | multiple live/account gaps; prove faster capability validation before polish | defer |

Ordinal ranking avoids unsupported numeric precision. Local continuity wins this
cycle because every stronger candidate needs trustworthy selected local state,
and both install and default isolation had immediate concrete falsifiers. It
is a critical unblocker, not the whole beta. Browser/account evidence remains the
highest-value follow-up.

Harvest assay:

- **Reuse** present host compilation/router, real vivim-law and Vault. Same-repo
  provenance: f03905e; no external source copied or license newly assumed.
- **Adapt** the existing Vault integration restart pattern into real CLI
  subprocess tests using untouched default composition and two selected roots.
- **Reject** wholesale restoration of omitted historical tooling/agent machinery
  as the first step; it adds dependencies without resolving selected data truth.
- **Evidence only** existing simulated browser redaction/provenance/session bars;
  adapt after a real transport has been evidenced.
- **Evidence only** Chrome CDP versus debugger-extension transport alternatives.
  Chrome 136+ requires a nondefault profile for remote-debugging switches;
  installed/logged-in Chrome is not proof of attachable CDP. Sources:
  [Chrome remote debugging](https://developer.chrome.com/blog/remote-debugging-port?hl=en),
  [extension debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger).
- **Reject** the AI API leg as a shortcut substitute for browser-mediated V1.

Selected proof: clean locked installation, local continuity/isolation tests,
independent code/TypeScript review, local CLI process evidence, and existing
Vault/policy regressions. Browser captures and cross-driver CI wrappers are absent;
their suites remain visible in broad tests and are outside the named quick slice.
Broad failures remain a separate blocked claim.
After proof, rerank using actual transport/account constraints, not provider count.
