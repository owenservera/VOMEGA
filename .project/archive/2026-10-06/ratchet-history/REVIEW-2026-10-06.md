# Ω Proof Ratchet — independent review and hardening pass (2026-10-06)

Scope: the `experimental/ratchet` engine and the 80-gate D1 executable
specification, as landed from the external `vomega-ratchet-d1.patch` and then
hardened under `.project/RATCHET-ROUND1-INTEGRATION-DIRECTIVE.md`.

Branch: `work/d1-ratchet-integration` (base `bf0f5dc`; Round1 assay commit
`8695132`). Source SHA of the patch base: `bddb8cb`. Raw artifacts stay
uncommitted under `.local/external-assay/`.

Two independent reviewers (one for the engine, one for the D1 gate spec) did
not write this code and worked read-only. This document records what they found,
what was fixed, and what remains — it is a coordination/evidence record, not
project authority.

## 1. Verdict summary

| Question | Answer |
| --- | --- |
| Is the ratchet a sound **advisory** control plane? | Yes: state is computed, regressions outrank frontier work, expired claims vanish, drift never rewrites truth, SIMULATED is not presented as live. |
| Is it a sound **hard ratchet** for D1? | Yes after this pass for the C1–C4 guarantees and the ten defects below. Residual limits are documented in §5. |
| Is the 80-gate spec a faithful definition of done? | Substantially yes (behavioral gates through one port; the hard distinctions are genuinely pinned). Specific weak gates and coverage gaps remain (§4). |
| Does D1 work today? | No. Probe truth is **15/80** gates green; 65 red (`NotImplemented[D1-xxx]`). Ratchet-mode green (`d1:gates`) is **not** completion. |

### Defects found and their disposition

| ID | Defect | Fix |
| --- | --- | --- |
| D1 | `surfacesOverlap` had a wildcard false negative (`src/foo*.ts` vs `src/foobar.ts`) → two fan-out tasks could share a file | `packet.ts` now also matches each surface as a `Bun.Glob` against the other's literal value/prefix; unparseable patterns conflict |
| D2 | A new, never-anchored gate file bypassed C1; only `anchor --force` could add files, erasing lineage | new `anchor --add` silently-free path for new files; `UNANCHORED_GATE_FILE` now escalates to a problem under `check --strict` |
| D3 | `anchor --force` overwrote the whole anchor map with no reason and no lineage | `--force` now requires `--reason` and records a `SpecChange` (from→to) per changed/added/removed file |
| D4 | Anchor scope covered only `*.test.ts`, not shared gate helpers | anchors now cover **all** files under the gate dirs (`_gate.ts`, `_helpers.ts`, `_release.ts` included) |
| D5 | C1 drift was advisory and ignored by `review`/`complete` | `review` refuses a task whose gates are spec-changed; `complete` refuses while any anchor drift is unresolved |
| D6 | `promote` exit code ignored partial refusals | `promote --task` now exits non-zero if any of the task's gates was refused |
| D7 | Anchor/promotion digests were raw-byte and CRLF-sensitive → every anchor would drift on a fresh Windows checkout | `fileDigest` normalizes CRLF before hashing |
| D8 | Review independence defeated by label case/space variance (`impl` vs `Impl`) | labels compared normalized (`normalizeLabel`) in `authorsOf`/`acceptedIndependentReview`/`review` |
| D9 | `check` never validated board/evidence freshness → a hand-edited `d1-ratchet.json` could satisfy D1-083/084/085 | `check` regenerates both projections; evidence is a hard problem (state-bearing content compared with environment-volatile fields stripped), board is a warning |
| D10 | With a missing/stale `last-probe.json`, `status` could show stale states as green | `status` now warns when the last probe's HEAD differs from HEAD |

Also fixed (found during hardening, not in the review list): `check`/`graph --check`
reported `TASKGRAPH_STALE` on any fresh Windows checkout because the byte
comparison rejected CRLF (`sameText` normalizes line endings).

Verification: `bun run ratchet:test` grew from 18 to **24** tests (new C1
anchoring tests, wildcard-surface test, label-normalization test); the D1/D3/D9
reproductions were re-run against the CLI and now behave correctly; `check
--strict` is clean.

## 3. Phase E — D1 executable-specification validation

- **Coverage:** 80 gates across 9 files; every one of the 13 release-gate areas
  of `D1-FIRST-RELEASE-SPEC.md` §13 has at least one gate **except #13**
  (existing `nlcl`/`omega:quick` green), which is proven by baseline artifacts
  and `ratchet check`, not by a gate. §13.2 (explicit target beats default/prior)
  is only partially represented — no gate exercises a defaulted or prior World.
- **Distinctions preserved** (spot-verified against the gates): synthetic
  provenance enforcement; no silent Account selection; typed/clicked parity on
  `commandDigest`; stale-result suppression; consent as its own action (prose
  never grants it); reflection read-only + source-bound help with removal and
  drift tests; virtual receipts `SIMULATED` and rejected by the live predicate;
  failure simulation failing; deterministic replay. Two are **partial**:
  Provider/Account/Model/Session separation lacks a dedicated *Session* gate;
  Reflection "grants no authority/availability/authenticity/maturity" (addendum
  §7.4) has no gate.
- **Weak gates (flagged, not yet changed):** the metric gates D1-074..077 are
  constant-satisfiable (nothing recomputes the rates from the scenario corpus);
  D1-003 is an always-true OR kept as a defect demonstration; D1-055 and D1-010
  contain near-tautological assertions; artifact proofs D1-002/085/086/087/088
  are substring `contains` checks.
- **Fixed:** D1-057 ("every reflected fact is copied from its anchor, never
  invented") previously **skipped** a fact whose key was absent from the anchor,
  so fabricated facts passed. It now asserts the key is present and equal.
  Changed under the C1 protocol with a recorded `spec-change`.

## 4. Remaining limitations (recorded, not hidden)

1. Reviewer identity is a coordination label, not proof of independent actors
   (C2). The engine enforces label separation only.
2. §13.2 default/prior precedence has no gate; the open question in
   `DESIGN.md` §8.2 is still open.
3. Addendum §7.4 (Reflection grants nothing) and realization/action-drift
   grounding have no dedicated gate.
4. Metric gates are constant-satisfiable until `metrics.ts` is implemented and
   a gate recomputes the rates from the scenario corpus.
5. Release gate #13 remains artifact/baseline-only by design.
6. `anchor --add` treats a brand-new gate file as an expansion (no reason
   required); only changes to *existing* anchored content require a
   `spec-change`. This is intentional but worth watching.

## 6. Recommendation

**ADOPT WITH REMAINING LIMITATIONS** — adopt the ratchet as the D1 execution
control layer on the strength of §2 (all C1–C4 guarantees hold and are tested),

completion; do not read `DONE` as proof of two independent real actors without
an out-of-band identity check.
